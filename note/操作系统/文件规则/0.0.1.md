# 开发文件存放规则

> 版本：0.0.1（市场调研 + 规则草案）
> 日期：2026-10-20
> 目标机器：Lenovo Legion Y7000P IRH8 / Ubuntu 26.10 / i7-13700H / 16GB
> 适用范围：本机开发项目、笔记库、素材、数据与备份
> 文档状态：待评审，未执行批量迁移
> 关联文档：[开发环境清单](../../开发资源/开发环境/README.md)、[系统升级方案](../系统升级方案/0.0.1.md)
> 核心原则：一个文件只有一个归属、可重现、可迁移、可清理、安全默认

---

## 0. 快速规则

先记住这 10 条，细节见后续章节。

1. 代码进 Git，密钥不进 Git。
2. 依赖、构建产物、缓存、日志都能重新生成，一律不入库。
3. 单文件超过 5MB、数据集、模型、视频放 `/data`，仓库只留清单。
4. 一个目录只属于一个 Git 仓库，项目和笔记不互相嵌套。
5. 代码和构建路径用 ASCII 小写短横线；文档可以用中文，但不带空格。
6. 日期用 `YYYY-MM-DD`，版本用语义化版本 `MAJOR.MINOR.PATCH`。
7. 项目自己写的文档进 `docs/`，外部资料进 `资料/`，生成物进 `artifacts/` 或 `/data`。
8. `.env` 只放本地，`.env.example` 入库。
9. 备份遵循 3-2-1；`/data` 与 `/` 在同一块物理盘上，不算独立备份。
10. 仓库根目录只放入口文件和配置，不放临时文件、截图和安装包。

## 1. 背景与目标

### 1.1 当前现状

数据来自 2026-10-20 的只读检查。

| 项目 | 现状 | 风险 |
|---|---|---|
| 笔记仓库 | `/home/bot/项目/other`，Git 仓库 | 同时承载笔记和项目 |
| 项目目录 | `item/init/argi-system`，内含独立 `.git` | 与笔记仓库形成嵌套仓库，外层无法正确跟踪 |
| 项目体积 | 52MB，其中 `.git` 38MB、`资料/` 9.1MB | 资料与代码混放，后续会继续膨胀 |
| 项目文档 | `docs/` 为空，文档集中在 `资料/项目开发文件/` | 文档与代码分离，交接和检索成本高 |
| 数据分区 | `/dev/sda4` 595GB，已挂载到 `/data` | 大文件可移出根分区；与 `/` 同盘，仍需异地备份 |
| 磁盘关系 | `/`（sda3）与 `/data`（sda4）在同一块 sda 上 | 备份到 `/data` 无法抵御整盘故障 |
| 双系统 | NVMe 上是 Windows，另有 651GB NTFS 分区 | 在 NTFS 上放 Git 仓库会有权限、大小写和符号链接问题 |

### 1.2 目标

1. 拿到任何新文件，能在几秒内判断该放哪。
2. 仓库克隆下来即可构建，不依赖本机绝对路径和个人配置。
3. 磁盘占用可解释、可清理、可迁移。
4. 密钥、大文件、生成物不进入 Git 历史。
5. 项目交接时，代码、文档、资料、数据边界清晰。

### 1.3 非目标

- 不对现有目录做全盘重命名或大规模搬迁；
- 不强制所有目录改成英文；
- 不引入 DVC、Git LFS 或对象存储，除非出现明确需求；
- 不调整分区、不修改系统目录结构；
- 不追求“零缓存”式的极简，缓存该用就用。

### 2.2 系统层：FHS

FHS 把系统目录按“可共享/不可共享、静态/可变”划分。对本机有意义的目录：

| 目录 | 标准用途 | 本机约定 |
|---|---|---|
| `/usr` | 发行版提供的程序、库、只读数据 | `apt` 安装的软件，不手工修改 |
| `/usr/local` | 本机自行安装的软件 | 官方 tar 包、源码编译（如 Go） |
| `/opt` | 附加的独立应用包 | Qoder、OpenCode、Bruno 等大型应用 |
| `/etc` | 系统级配置 | 只放配置，不放项目源码和数据 |
| `/var` | 运行中会变化的数据 | Docker、数据库、日志、缓存服务 |
| `/srv` | 对外提供服务的数据 | 本机开发不使用，避免和 `/data` 混淆 |
| `/home` | 用户文件 | 笔记、项目代码、用户配置 |
| `/tmp` | 临时文件 | 重启即弃，不放需要保留的内容 |
| `/run` | 运行时状态 | 由系统管理，不手工放文件 |

结论：系统目录只放“安装物”和“系统运行数据”，项目源码一律放用户目录。

### 2.3 用户层：XDG

XDG 规范把用户级文件拆成配置、数据、状态、缓存和运行时五类：

| 变量 | 默认值 | 放什么 | 能否删除 |
|---|---|---|---|
| `XDG_CONFIG_HOME` | `~/.config` | 应用配置 | 删了会丢配置 |
| `XDG_DATA_HOME` | `~/.local/share` | 应用数据、数据库、持久内容 | 删了会丢数据 |
| `XDG_STATE_HOME` | `~/.local/state` | 日志、历史、上次运行状态 | 一般可删 |
| `XDG_CACHE_HOME` | `~/.cache` | 可重新生成的缓存 | 随时可删 |
| `XDG_RUNTIME_DIR` | `/run/user/<uid>` | 套接字、锁、临时运行时文件 | 注销即清 |

结论：不要把配置、数据、缓存全塞进一个目录；应用不要往家目录根部散放点文件。

### 2.4 项目层：遵循语言生态默认布局

主流生态都已经有稳定约定，自创结构会增加工具适配成本。

| 生态 | 标准布局 | 构建产物 |
|---|---|---|
| Java / Maven | `src/main/java`、`src/main/resources`、`src/test/java`、`src/test/resources` | `target/` |
| Node / Vue / Vite | `src/`、`public/`、根级 `package.json` 和 `vite.config.js` | `dist/` |
| Python | `src/<包名>/`、`tests/`、`pyproject.toml` | `.venv/`、`__pycache__/` |
| Go | `cmd/`、`internal/`、`pkg/`、`go.mod` | `bin/` |
| Rust | `src/`、`tests/`、`Cargo.toml` | `target/` |

结论：单栈项目直接用生态默认布局；多端项目用“按端分目录”的方式组合，不把各端源码混在一个 `src/` 里。

### 2.5 文档层：README、docs、ADR 与 Diátaxis

- **README** 是仓库入口，说明项目是什么、怎么跑、目录怎么读。
- **docs-as-code**：文档和代码同仓、同评审、同版本，使用 Markdown 和相对链接。
- **ADR（架构决策记录）**：把重要决策、背景、后果写在 `docs/adr/`，文件名带序号，例如 `0001-use-postgresql.md`。
- **Diátaxis** 把文档分为四类：教程（学习）、操作指南（任务）、参考（信息）、解释（原理）。个人项目不必严格四分，但应避免把四类内容混在一篇文档里。

实证数据（2026 年对 GitHub 仓库的研究）显示，主流仓库中：

| 文件/目录 | 出现比例 |
|---|---|
| `README.md` | 95.3% |
| `.gitignore` | 95.0% |
| `.github/` | 82.5% |
| GitHub Workflows | 77.3% |
| `LICENSE` | 73.1% |
| `src/` | 60.1% |
| `docs/` | 37.4% |
| `tests/` | 35.5% |

结论：README 和 `.gitignore` 已是事实标准；`docs/` 和 `tests/` 是区分项目可维护性的关键项。

### 2.6 命名层：ISO 8601 与跨平台安全字符

科研数据管理和主流工程实践的共同建议：

- 日期用 ISO 8601：`YYYY-MM-DD` 或 `YYYYMMDD`，保证按时间排序；
- 文件名不用空格，用 `-` 或 `_`；
- 尽量用小写，避免大小写不敏感文件系统上的冲突；
- 避免 `\ / : * ? " < > |` 等保留字符；
- 不用 `final`、`new`、`copy`、`副本`、`(1)` 这类无法排序和追溯的命名；
- 版本号用语义化版本，文件名中只在文档和发布包中出现。

### 2.7 大文件层：Git 不是网盘

- Git 保存的是文本差异，二进制和大文件会让仓库历史迅速膨胀，且无法有效压缩。
- GitHub 对单文件 50MB 给出警告、100MB 直接拒绝；仓库总体积也会影响克隆速度。
- 常见方案：
  - **Git LFS**：适合必须随仓库版本化的二进制资产（设计稿、字体、少量图片）；
  - **DVC**：适合数据集和模型，仓库只保存元数据，数据放远端；
  - **外部存储 + 清单**：本地开发最轻量，文件放 `/data`，仓库记录路径、校验值和来源；
  - **对象存储**：团队协作或需要公网访问时使用。

结论：本机优先“外部存储 + 清单”，确有版本化需求再上 LFS；DVC 和对象存储暂不引入。

### 2.8 安全层：密钥与仓库分离

主流安全实践一致要求：

- 密钥、令牌、数据库密码永不提交到仓库；
- 本地放 `.env`，仓库只提交 `.env.example`；
- 密钥文件权限设为 `600`；
- 文档、截图、脚本示例中同样不能出现真实密钥；
- 一旦泄露，先轮换密钥，再清理 Git 历史，不能只删文件了事。

### 2.9 备份层：3-2-1

3-2-1 原则：至少 3 份数据，存放在 2 种不同介质上，其中 1 份在异地。

对开发机的含义：

- Git 远端是代码的副本，但未提交的工作、未跟踪的素材、数据库不在其中；
- 同一块物理盘上的两个分区不算两份介质；
- 备份必须定期做恢复演练，没验证过的备份等于没有备份。

### 2.10 调研结论

| 做法 | 来源 | 决定 | 理由 |
|---|---|---|---|
| FHS 系统目录划分 | FHS 3.0 | 采纳 | 避免项目污染系统目录 |
| XDG 用户目录划分 | XDG 规范 | 采纳 | 配置、数据、缓存边界清晰 |
| 语言生态默认布局 | Maven / Python / Node 官方 | 采纳 | 工具零配置，降低维护成本 |
| README + `.gitignore` | 实证研究 | 强制 | 已是事实标准 |
| `docs/` + 轻量 ADR | docs-as-code / ADR | 采纳 | 个人项目可控，收益高 |
| Diátaxis 四分类 | Diátaxis | 部分采纳 | 用于组织文档，不强制建四套目录 |
| Git LFS | Git LFS 实践 | 按需 | 只在必须版本化二进制时启用 |
| DVC / 对象存储 | DVC / 云存储实践 | 暂不 | 当前规模用 `/data` 足够 |
| 3-2-1 备份 | 行业通用 | 采纳 | 开发机单盘风险高 |
| 全 ASCII 命名 | 跨平台实践 | 部分采纳 | 代码路径强制，文档目录允许中文 |
| 阿里巴巴应用分层 | 阿里巴巴 Java 开发手册 | 参考 | 后端包结构参考，不照搬全部规约 |

## 3. 总体规则

### 3.1 七条原则

1. **单一归属**：同一类文件只放一个地方，不产生“两个都像正式版本”的副本。
2. **源与产物分离**：源码、文档、资料是源；构建产物、日志、截图是产物，产物可删。
3. **源与数据分离**：代码进 Git，数据进 `/data`，仓库不承担数据存储。
4. **密钥与仓库分离**：密钥只存在本机或密码管理器，仓库只留模板。
5. **遵循生态默认**：有官方布局就用官方布局，不为了“整齐”自创目录。
6. **可迁移**：仓库内只用相对路径和环境变量，不写 `/home/bot/...`。
7. **可清理**：所有可重新生成的内容集中到已知目录，并加入 `.gitignore`。

### 3.2 新文件决策树

```text
新文件
├─ 含密钥/凭据？
│   ├─ 是 → .env（chmod 600，不入库）或 ~/.config/<app>/
│   └─ 否 ↓
├─ 可重新生成（依赖、构建、缓存、日志）？
│   ├─ 是 → 对应缓存/产物目录，加入 .gitignore
│   └─ 否 ↓
├─ 单文件 >5MB、数据集、模型、视频？
│   ├─ 是 → /data/<类别>/，仓库只留清单或说明
│   └─ 否 ↓
├─ 项目自己产出的文档？
│   ├─ 是 → docs/
│   └─ 否 ↓
├─ 外部参考资料、原型、第三方文档？
│   ├─ 是 → 资料/（小）或 /data/assets/（大）
│   └─ 否 ↓
├─ 源代码、测试、配置模板？
│   ├─ 是 → 按技术栈默认目录（src/、tests/ 等）
│   └─ 否 ↓
└─ 一次性试验/临时文件 → sandbox/ 或 /tmp，定期清理
```

### 3.3 五层存储模型

| 层级 | 位置 | 内容 | 进 Git | 备份 | 可清理 |
|---|---|---|---|---|---|
| T0 工作区 | `~/项目/` | 笔记、活跃项目源码 | 是 | 远端 + 本地 | 否 |
| T1 大数据 | `/data/` | 素材、数据集、模型、备份、归档 | 否 | 是 | 按保留策略 |
| T2 缓存 | `~/.cache/`、项目内依赖和产物 | 缓存、依赖、构建、日志 | 否 | 否 | 随时 |
| T3 安装 | `/opt`、`/usr/local`、`~/.local` | 应用、工具链、CLI | 否 | 否 | 重装即可 |
| T4 配置 | `~/.config/`、`/etc` | 应用配置、系统配置 | 部分 | 是 | 否 |
| T5 归档 | `/data/archive/`、Git 远端 | 完结项目、历史版本 | 视情况 | 是 | 按保留策略 |

## 4. 系统层存放规则

### 4.1 本机磁盘现状

| 设备 | 大小 | 类型 | 挂载点 | 说明 |
|---|---|---|---|---|
| `/dev/sda1` | 1GB | vfat | `/boot/efi` | EFI 分区 |
| `/dev/sda2` | 149GB | swap | 未启用 | 系统升级方案中暂不调整 |
| `/dev/sda3` | 186.3GB | ext4 | `/` | 已用约 18GB，可用约 156GB |
| `/dev/sda4` | 595.2GB | ext4 | `/data` | 已挂载，`nofail`，属主 `bot:bot` |
| `/dev/nvme0n1` | 953.9GB | NTFS | 未挂载 | Windows 与共享数据，不作为开发仓库 |

两条硬规则：

1. **Git 仓库只放在 ext4 上**。NTFS 缺少可靠的 Unix 权限和符号链接语义，双系统切换后容易出现权限、换行和文件模式异常。
2. **`/data` 与 `/` 同盘**。把备份放在 `/data` 只能防误删，不能防整盘故障；异地备份必须另找介质。

### 4.2 路径总表

| 内容 | 路径 | 依据 | 当前状态 |
|---|---|---|---|
| 系统软件 | `/usr` | FHS + apt | 已使用 |
| 手动安装的大型应用 | `/opt/<name>` | FHS | 已有 Qoder、OpenCode |
| 源码编译的工具链 | `/usr/local` | FHS | 预留 |
| 用户级 CLI | `~/.local/bin` | XDG | 预留 |
| 应用持久数据 | `~/.local/share/<name>` | XDG | 预留 |
| 应用状态/日志 | `~/.local/state/<name>` | XDG | 预留 |
| 应用配置 | `~/.config/<name>` | XDG | 已使用 |
| 应用缓存 | `~/.cache/<name>` | XDG | 已使用 |
| 运行时文件 | `/run/user/1000` | XDG | 系统管理 |
| 安装包缓存 | `~/Downloads/software/<tool>/<version>/` | 本机约定 | 建议建立 |
| 笔记与项目 | `~/项目/` | 本机约定 | 已使用 |
| 大素材、数据集、模型 | `/data/<类别>/` | 本机约定 | 已挂载并建立骨架 |
| 备份 | `/data/backups/` + 外置介质 + 异地 | 3-2-1 | 部分缺失 |
| 临时文件 | `/tmp` | FHS | 系统管理 |
| 数据库数据 | `/var/lib/<db>` 或容器卷 | FHS | 待安装 |

### 4.3 不要放的地方

| 禁止 | 原因 |
|---|---|
| 在 `/usr`、`/opt`、`/etc` 放项目源码 | 系统升级、重装、权限管理都会出问题 |
| 在家目录根部散放项目（如 `~/myproject`） | 家目录被点文件和临时目录淹没，备份边界不清 |
| 在 `/tmp` 放需要保留的文件 | 重启或清理策略会删除 |
| 在 NTFS 分区初始化 Git 仓库 | 权限、大小写、符号链接、换行符均不可靠 |
| 把数据库数据目录放项目内 | 备份、权限、升级都会和代码耦合 |
| 用 `sudo` 创建项目文件 | 产生 root 属主，后续编辑和 Git 操作受阻 |
| 在仓库内放安装包、镜像、模型 | 仓库体积失控，无法有效 diff |

### 4.4 `/data` 目录规划

挂载已于 2026-10-20 完成，步骤见[系统升级方案 1.3](../系统升级方案/0.0.1.md)。目录骨架已建立，属主为 `bot:bot`。

```text
/data/
├── assets/          # 图片、视频、字体、音频等大素材
├── datasets/        # 训练/测试数据集、爬取原始数据
├── models/          # AI 模型权重、离线模型包
├── backups/
│   ├── db/          # 数据库导出
│   ├── projects/    # 项目快照或裸仓库镜像
│   └── system/      # 系统配置备份（Timeshift 另设目录）
├── archive/         # 已完结项目、历史交付物
├── temp/            # 可随时删除的中间产物
└── README.md        # 记录每个一级目录的用途、保留期和负责人
```

约定：

- 一级目录固定，不在 `/data` 根部随手建目录；
- 每个一级目录放一个 `README.md`，写明来源、保留策略和清理方式；
- `/data` 不放活跃 Git 工作区，只放数据和归档；
- 需要按项目区分时，在类别下建项目子目录，例如 `/data/assets/argi-system/`；
- 删除前先确认没有项目通过配置或脚本引用该路径。

### 4.5 符号链接规则

- 允许用符号链接把 `/data` 的大素材接入项目，例如项目内 `assets` 指向 `/data/assets/<project>`；
- 指向仓库外的符号链接**不要提交**，加入 `.gitignore`，否则换机器后全部失效；
- 更推荐用 `.env` 或配置文件记录素材根路径，例如 `ASSETS_ROOT=/data/assets/<project>`；
- 不使用跨分区、跨机器的相对符号链接。

## 5. 仓库与项目规则

### 5.1 工作区布局

当前结构存在嵌套仓库：外层 `other` 是 Git 仓库，内层 `argi-system` 也有 `.git`。外层提交 `item/` 时，Git 只会记录一个 gitlink，内层文件不会被跟踪。

短期最小改动，保持现有路径不变：

```text
~/项目/other/                 # 笔记仓库，只跟踪 note/
├── .gitignore                # 忽略 item/
├── note/                     # 笔记
└── item/                     # 项目容器，每个子目录是独立仓库
    └── init/argi-system/     # 独立 Git 仓库
```

外层 `.gitignore` 至少包含：

```gitignore
# 项目仓库独立管理，不纳入笔记仓库
/item/
```

中期建议，新项目与笔记仓库平级：

```text
~/项目/
├── other/                    # 笔记仓库
└── projects/
    ├── active/               # 进行中
    ├── archived/             # 已完结
    └── sandbox/              # 一次性试验
```

规则：

1. 一个目录只能属于一个 Git 仓库；
2. 笔记仓库只放笔记，项目仓库只放项目；
3. 不嵌套 Git 仓库；需要聚合时用 submodule 并明确记录，否则保持独立目录；
4. 新项目目录名用 ASCII 小写短横线，例如 `agri-system`；
5. 项目归档时移动整个仓库到 `archived/` 或 `/data/archive/`，不要只复制源码。

### 5.2 通用项目骨架

```text
<project>/
├── README.md              # 项目入口：是什么、怎么跑、目录说明
├── .gitignore             # 忽略规则，按类别分组注释
├── .editorconfig          # 跨编辑器缩进和换行约定
├── .env.example           # 环境变量模板，不含真实密钥
├── docs/                  # 项目文档
│   ├── README.md          # 文档索引
│   ├── adr/               # 架构决策记录
│   ├── design/            # 设计、接口、数据模型
│   └── ops/               # 部署、运维、排障
├── src/                   # 单栈项目源码；多端项目改为按端分目录
├── tests/                 # 测试
├── scripts/               # 仓库自动化脚本
├── deploy/                # Dockerfile、compose、Nginx、CI 部署配置
├── assets/                # 小型、可入库的图片和字体
└── 资料/                  # 外部参考、需求原件、原型（可选）
```

根目录只放入口文件和配置。临时文件、截图、报告、日志、安装包一律不放根目录。

### 5.4 `docs/` 与 `资料/` 的边界

| 内容 | 放 `docs/` | 放 `资料/` | 放 `/data` |
|---|---|---|---|
| 项目自己写的设计与方案 | 是 | 否 | 否 |
| API 文档、数据库设计 | 是 | 否 | 否 |
| 架构决策记录 | 是（`docs/adr/`） | 否 | 否 |
| 部署与排障手册 | 是（`docs/ops/`） | 否 | 否 |
| 需求原件、会议记录、第三方文档 | 否 | 是 | 大文件放这里 |
| 原型 HTML、参考截图 | 否 | 是（小） | 大图集放这里 |
| 爬取的原始数据、数据集 | 否 | 否 | 是 |
| 脚本生成的截图、测试报告 | 否 | 否 | 是，或 `artifacts/` |

约定：

- `docs/` 用 Markdown，链接用相对路径，确保仓库移动后仍可用；
- 文档多时用编号前缀，如 `01-需求分析.md`、`02-数据库设计.md`，保证排序；
- `资料/` 保留原始格式（`.docx`、`.pdf`、`.html`），文件名加日期或编号，避免“最终版”；
- `docs/README.md` 作为索引，列出文档用途和阅读顺序；
- 不要把生成物放进 `资料/`，否则每次运行都会污染仓库；
- 现有 `docs/` 为空而文档全在 `资料/` 的情况，在下次改动相关文档时逐步迁入，不强制一次性搬完。

### 5.5 `scripts/` 与 `deploy/`

- `scripts/` 放仓库内自动化脚本，使用相对路径，从仓库根目录执行；
- Shell 脚本以 `#!/usr/bin/env bash` 开头，并启用 `set -euo pipefail`；
- 不在脚本里写死 `/home/bot/...`，用 `$(git rev-parse --show-toplevel)` 或环境变量定位仓库；
- `deploy/` 放 Dockerfile、compose、Nginx、Kubernetes 清单和发布脚本；
- CI 配置放 `.github/workflows/`，与 `deploy/` 分开，避免部署逻辑和流水线逻辑混在一起。

### 6.1 分类表

| 文件类型 | 存放位置 | 入库 | 备份 | 说明 |
|---|---|---|---|---|
| 源代码 | `src/`、`backend/`、`frontend/` 等 | 是 | 是 | 按生态默认布局 |
| 测试 | `tests/`、`src/test/` | 是 | 是 | 测试数据小文件可入库 |
| 项目文档 | `docs/` | 是 | 是 | Markdown + 相对链接 |

| 小型静态资源 | `assets/`、`public/` | 是 | 是 | 单文件建议 <1MB |
| 大型素材 | `/data/assets/` | 否 | 是 | 仓库留清单 |
| 数据集、模型 | `/data/datasets/`、`/data/models/` | 否 | 是 | 仓库留版本和校验值 |
| 依赖目录 | `node_modules/`、`.venv/`、`vendor/` | 否 | 否 | 用锁文件恢复 |
| 构建产物 | `dist/`、`target/`、`build/` | 否 | 否 | 可重新生成 |
| 缓存 | `~/.cache/`、`.pytest_cache/`、`__pycache__/` | 否 | 否 | 随时可删 |

| 数据库导出 | `/data/backups/db/` | 否 | 是 | 含真实数据，不入库 |
| 密钥与凭据 | `.env`、`~/.config/<app>/` | 否 | 密码管理器 | 权限 600 |
| 本地配置 | `.env`、`application-local.yml` | 否 | 否 | 仓库只留 example |
| 截图、测试报告 | `artifacts/` 或 `/data` | 否 | 按需 | 生成物 |
| AI 提示词 | `prompts/`、`docs/` | 是 | 是 | 不含密钥和隐私数据 |
| 模型权重 | `/data/models/` | 否 | 是 | 记录来源和哈希 |
| 临时文件 | `/tmp`、`tmp/` | 否 | 否 | 定期清理 |
| IDE 用户配置 | `.idea/`、`.vscode/` 的本地部分 | 否 | 否 | 团队共享配置放 `.vscode/settings.json` 并评审 |
| 安装包 | `~/Downloads/software/` | 否 | 否 | 保留校验值和最近一个版本 |

### 6.2 `.gitignore` 模板

按类别分组，便于后续维护：

```gitignore
# 依赖与构建产物
node_modules/
dist/
build/
target/
out/
*.class
*.jar
__pycache__/
*.py[cod]
.venv/
venv/

# 缓存与测试产物
.cache/
.pytest_cache/
.mypy_cache/
.ruff_cache/
coverage/
reports/
artifacts/
*.log
*.pid

# 密钥与本地配置
.env

!.env.example

application-local.yml

# IDE 与系统文件

.DS_Store
Thumbs.db

# 大文件与数据
/data/

```

注意：

- 不要用 `git add -A` 或 `git add .` 盲加，先看 `git status`；
- `.gitignore` 只对未跟踪文件生效，已经提交的密钥或大文件需要单独处理；
- 团队共享的编辑器配置可以入库，个人配置不入库，两者要分开。

### 6.3 大文件规则

| 阈值 | 处理 |
|---|---|
| 单文件 <1MB | 可以直接入库，如图标、小图、示例数据 |
| 单文件 1–5MB | 谨慎入库，确认是源素材而非生成物 |
| 单文件 >5MB | 默认放 `/data`，仓库记录清单 |
| 单文件 >50MB | 不入库；必须版本化时用 Git LFS |
| 仓库总体积 >100MB | 检查历史，考虑拆分仓库或清理大文件 |

本地大文件清单建议放在仓库内，例如 `assets/README.md`：

```markdown
| 文件 | 来源 | 大小 | SHA256 | 日期 |
|---|---|---|---|---|
| pest-images.tar.gz | 内部素材库 | 1.2GB | <sha256> | 2026-10-20 |
```

排查仓库内大文件：

```bash
find . -type f -not -path './.git/*' -size +5M \
  -printf '%s\t%p\n' | sort -nr | head -20
```

检查 Git 历史中的大对象（需要 git-filter-repo 或脚本，执行前先备份仓库）。

### 6.4 密钥与敏感文件

规则：

1. 真实密钥只放 `.env` 或 `~/.config/<app>/`，权限 `600`；
2. 仓库提交 `.env.example`，只写变量名、说明和占位值；
3. 不在文档、截图、录屏、提交信息、脚本示例中出现真实密钥；
4. 不把密钥作为命令行参数传入，避免进入 shell 历史和进程列表；
5. 不把 `~/.ssh`、云厂商凭据目录复制进项目；
6. 提交前用 `git diff --cached` 检查，必要时接入 `gitleaks` 或 `pre-commit`。

`.env.example` 示例：

```dotenv
# 数据库
DB_HOST=127.0.0.1
DB_PORT=5432
DB_NAME=app
DB_USER=app
DB_PASSWORD=change-me

# 第三方服务
AI_API_KEY=replace-with-your-key
```

泄露处置顺序：

1. 立即轮换或吊销密钥；
2. 用 `git filter-repo` 从历史中移除；
3. 强制推送并通知协作者重新克隆；
4. 检查日志、备份、截图是否还有残留。

## 7. 命名规则

### 7.1 目录命名

| 场景 | 规则 | 示例 |
|---|---|---|
| 项目根目录 | ASCII 小写，短横线分隔 | `agri-system`、`image-tools` |
| 代码与构建目录 | ASCII 小写 | `src`、`tests`、`deploy` |
| 笔记主题目录 | 允许中文，不带空格 | `操作系统`、`开发资源` |
| 资料分类目录 | 允许中文，不带空格 | `项目开发文件`、`数据库文件` |
| 隐藏配置目录 | 点开头，遵循工具约定 | `.github`、`.vscode` |

### 7.2 文件命名

| 类型 | 规则 | 示例 |
|---|---|---|
| 项目文档 | 编号或日期 + 主题 | `01-需求分析.md`、`2026-10-20-评审记录.md` |
| 版本化方案 | 主题目录下用版本号 | `系统升级方案/0.0.1.md` |
| 普通笔记 | 主题明确，避免泛化 | `文件规则/0.0.1.md` |
| 代码文件 | 遵循语言约定 | `UserService.java`、`useAuth.ts`、`data_loader.py` |
| 图片素材 | 用途-描述-尺寸 | `hero-banner-1920x1080.webp` |
| 数据文件 | 主题-日期 | `pest-images-2026-10-20.tar.gz` |
| 配置模板 | 原名 + `.example` | `.env.example`、`application-example.yml` |

### 7.3 日期与版本

- 日期统一 `YYYY-MM-DD`，例如 `2026-10-20`；
- 需要按时间排序的文件，日期放最前面；
- 文档版本用 `MAJOR.MINOR.PATCH`，沿用现有习惯：`0.0.x` 草案、`0.1.0` 评审通过、`1.0.0` 正式执行；
- Git 标签用 `v` 前缀，例如 `v1.2.3`；
- 文件名只在文档和发布包中出现版本号，源代码文件名不带版本号。

### 7.4 中文与跨平台

- 文件编码统一 UTF-8；
- 代码路径、构建路径、包名、脚本名、CI 配置使用 ASCII；
- 中文可以出现在笔记、文档正文和人类阅读的资料目录中；
- 文件名不带空格，不用全角标点；
- 避免 `\ / : * ? " < > |`、`#`、`%`、`&`、`{}`、`[]` 等字符；
- 假设文件系统大小写不敏感：同一目录不要出现仅大小写不同的文件名；
- 避免 Windows 保留名：`CON`、`PRN`、`AUX`、`NUL`、`COM1`–`COM9`、`LPT1`–`LPT9`；
- 路径总长度控制在 200 字符以内，方便压缩、同步和跨平台。

### 7.5 好例子与坏例子

| 推荐 | 不推荐 | 原因 |
|---|---|---|
| `01-需求分析.md` | `需求（最终版）.md` | 可排序、可追溯 |
| `2026-10-20-评审记录.md` | `10月20日评审.md` | ISO 日期跨年排序正确 |
| `agri-system` | `Agri System 项目` | 无空格、跨平台安全 |
| `DB_HOST` | `数据库地址` | 环境变量用大写蛇形 |
| `hero-banner-1920x1080.webp` | `banner 新.png` | 含义和尺寸明确 |
| `pest-images-2026-10-20.tar.gz` | `数据备份.tar.gz` | 主题和时间明确 |
| `0001-use-postgresql.md` | `数据库决策.md` | ADR 可排序、可引用 |

## 8. 临时、缓存与构建产物

### 8.1 临时文件

- 一次性的实验放 `sandbox/` 或 `/tmp`，不放在仓库根目录；
- 仓库内确有需要时用 `tmp/`，并在 `.gitignore` 中忽略；
- 提交前检查根目录是否出现 `test.md`、`tmp.txt`、`新建文本文档` 等文件；
- 编辑器交换文件、Office 锁文件、系统缩略图文件统一忽略。

### 8.2 缓存

| 缓存 | 位置 | 清理方式 |
|---|---|---|
| npm | `~/.npm` | `npm cache verify` |
| Node 依赖 | 项目 `node_modules/` | 删除后重新安装 |
| Python | `~/.cache/uv`、`__pycache__/`、`.pytest_cache/` | `uv cache clean`、删除目录 |
| Go | `~/go/pkg/mod`、`~/.cache/go-build` | `go clean -cache` |
| Rust | `~/.cargo`、项目 `target/` | `cargo clean` |
| Docker | `/var/lib/docker` | `docker system df` 后按需清理 |
| 应用缓存 | `~/.cache/<name>/` | 直接删除 |

### 8.3 构建产物与运行日志

- 构建产物使用工具默认目录：`dist/`、`target/`、`build/`、`out/`；
- 日志写入 `logs/` 或 `/var/log/`，不写入仓库根目录；
- 需要保留的测试报告、截图统一放 `artifacts/`，并加入 `.gitignore`；
- 需要长期保存的报告放 `/data/archive/<project>/`，仓库只留生成脚本；
- 定期清理前先用 `git clean -ndX` 预览将被删除的忽略文件，确认后再执行。

## 9. 备份规则

### 9.1 3-2-1 落地

| 副本 | 位置 | 覆盖内容 | 频率 |
|---|---|---|---|
| 第 1 份 | 本机工作区 | 全部活跃文件 | 实时 |
| 第 2 份 | `/data` 或外置硬盘/NAS | 项目、笔记、数据库导出、配置 | 每日或每周 |
| 第 3 份 | 异地（云盘、对象存储、异地机器） | 代码、笔记、关键数据 | 每周 |

### 9.2 本机现实约束

- `/` 和 `/data` 都在 `/dev/sda` 上，`/data` 备份只能防误删和文件损坏，不能防整盘故障；
- Windows 所在的 NVMe 是另一块盘，但它是双系统工作盘，不是异地备份；
- Git 远端只覆盖已提交的代码和文档，未提交工作、数据库、素材不在其中；
- 备份文件应加密，尤其是包含密钥、数据库导出和个人资料的备份。

### 9.3 分类备份矩阵

| 数据 | 备份方式 | 保留 | 恢复验证 |
|---|---|---|---|
| 笔记与项目代码 | Git 远端 + `/data/backups/projects` | 永久 + 最近 3 个快照 | 每季度克隆一次 |
| 数据库 | `pg_dump` / `mysqldump` 到 `/data/backups/db` | 最近 7 天 + 每月 1 份 | 每季度恢复一次 |
| 大素材、数据集、模型 | 外置硬盘/NAS + 异地 | 按项目生命周期 | 每半年校验哈希 |
| 用户配置 | dotfiles 仓库或手工导出 | 最近 1 份 | 新机器安装时验证 |
| 系统 | Timeshift | 3–5 个快照 | 升级前验证 |
| 密钥 | 密码管理器 | 永久 | 每季度检查可登录 |

### 9.4 恢复演练

- 每季度至少恢复一个文件、一个项目和一个数据库；
- 恢复后验证哈希、构建和启动；
- 记录恢复耗时和缺失项，更新本规则；
- 没有演练过的备份，不视为可用备份。

### 9.5 不需要备份

- 依赖目录、构建产物、缓存、日志、临时文件；
- 容器镜像和容器本身（用 compose 和 Dockerfile 重建）；
- 系统安装文件（重装即可）；
- 可从官方源重新下载的安装包。

## 10. 权限规则

| 对象 | 权限 | 说明 |
|---|---|---|
| `~/.ssh` | `700` | 仅本人可进入 |
| 私钥、`.env` | `600` | 仅本人可读写 |
| 公钥、`.env.example` | `644` | 可读 |
| 普通目录 | `755` | 默认 |
| 敏感数据目录 | `700` | 仅本人 |
| 共享数据 | 目录 `750`、文件 `640` | 按组共享 |
| 可执行脚本 | `755` | 需要执行位 |

规则：

- 不使用 `chmod 777`；
- 不用 `sudo` 创建项目文件；
- 新机器默认 `umask 022`，敏感目录单独收紧到 `077`；
- `/var/run/docker.sock` 位于 tmpfs，重启后重建，`setfacl` 授权不会持久；需要长期使用时加入 `docker` 组或配置 systemd drop-in，但两者都等同于 root 权限，仅限单用户可信机器；
- 定期检查异常权限：

```bash
find ~/.ssh -type f -perm /077
find ~/项目 -user root -maxdepth 3
```

## 11. 迁移与执行

### 阶段 0：确认（不改动）

- [ ] 确认 `/data` 是否按系统升级方案挂载；
- [ ] 确认笔记仓库与项目仓库是否拆分；
- [ ] 确认新项目默认位置；
- [ ] 确认是否接受代码路径全 ASCII。

### 阶段 1：低风险准备（不移动文件）

1. 按系统升级方案挂载 `/data` 并确认属主；
2. 创建 `/data` 一级目录和说明文件；
3. 在笔记仓库根目录添加 `.gitignore`，忽略 `/item/`；
4. 为新项目准备 README、`.gitignore`、`.editorconfig`、`.env.example` 模板；
5. 在笔记仓库补充本规则的入口链接。

### 阶段 2：新项目执行

- 所有新项目按第 5 节骨架创建；
- 旧项目只补缺失的 README、`.gitignore`、`.env.example`，不做无关重排；
- 新产生的大文件直接放 `/data`，不再进仓库。

### 阶段 3：可选迁移

- 将 `资料/` 中的大素材、截图集迁移到 `/data/assets/<project>/`；
- 将项目文档从 `资料/项目开发文件/` 逐步迁入 `docs/`；
- 解决嵌套仓库：保留项目独立仓库，外层忽略 `item/`；
- 归档已完结项目到 `/data/archive/`；
- 修正明显不合理的命名，但不为了统一而批量改名。

迁移规则：

- 只用 `mv`，不删除；
- 迁移前记录清单：源路径、目标路径、大小、校验值；
- 迁移后更新项目内的路径配置和文档链接；
- 迁移失败可原路移回。

### 回滚

| 操作 | 回滚方式 |
|---|---|
| 外层忽略 `item/` | 删除 `.gitignore` 中对应行 |
| 大素材迁到 `/data` | 按迁移清单移回原路径 |
| 文档迁入 `docs/` | 按清单移回 `资料/` |
| 新项目模板 | 直接删除模板文件，不影响已有代码 |
| `/data` 挂载 | 见系统升级方案回滚手册 |

## 12. 检查清单

### 12.1 新建项目

- [ ] 项目位于 ext4 分区，未放在 NTFS；
- [ ] 已 `git init`，且没有嵌套在另一个仓库中；
- [ ] 有 `README.md`、`.gitignore`、`.editorconfig`、`.env.example`；
- [ ] 目录结构符合对应技术栈默认布局；
- [ ] 没有提交依赖、构建产物、日志和密钥；
- [ ] 已配置远端并完成首次提交。

### 12.2 提交前

- [ ] `git status` 中没有 `.env`、密钥、数据库导出；
- [ ] `git diff --cached --stat` 中没有大文件和生成物；
- [ ] 锁文件已提交，依赖版本可复现；
- [ ] 文档链接为相对路径；
- [ ] 提交信息说明了“为什么”，不是只写“更新”。

### 12.3 每月

- [ ] 根分区剩余空间不低于 20%；
- [ ] `/data` 剩余空间不低于 20%；
- [ ] 仓库内没有超过 5MB 的意外文件；
- [ ] 缓存和不再使用的依赖已清理；
- [ ] 数据库导出有最近 7 天内的副本；
- [ ] 抽查一次备份恢复。

### 12.4 新机器

- [ ] 挂载 `/data`，创建一级目录；
- [ ] 配置 XDG 目录和必要的环境变量；
- [ ] 克隆笔记仓库和项目仓库；
- [ ] 从密码管理器恢复 `.env`，不通过聊天工具传输；
- [ ] 按 README 完成构建和启动验证；
- [ ] 配置备份和 Timeshift。
