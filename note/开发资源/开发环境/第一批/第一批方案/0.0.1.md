## 1. 目标与范围

第一批要搭好一套可直接写 Java 后端、连 MySQL、用 Neo4j 的开发环境。

本批安装：

| 类别 | 组件 |
|---|---|
| 基础工具 | curl、ca-certificates、gnupg、build-essential、unzip、zip、jq、tree、htop、vim、bash-completion |
| Java | OpenJDK 21 LTS |
| 构建 | Maven 3.9.x |
| 关系型数据库 | MySQL 8.4 LTS（Docker） |
| 图数据库 | Neo4j 5.26 LTS Community（Docker） |
| 容器运行时 | Docker Engine + Compose v2 |
| 配置与数据 | `~/dev-stack` 配置目录 + Docker 命名卷 |

本批**不做**：

- 不安装 MySQL 9.7 原生包（Ubuntu 26.10 源里只有创新版，不是 LTS）；
- 不安装 Neo4j 原生 tar 包，不把 Neo4j 和宿主 Java 版本绑定；
- 不安装 IDE、Node.js、Python、Android SDK；
- 不挂载 `/data`，不迁移现有数据；
- 不开放数据库到局域网，不做端口转发；
- 不安装 APOC/GDS，留到有明确需求时再加。

## 2. 版本选型

| 组件 | 选定版本 | 选择理由 | 稳定性 | 性能 |
|---|---|---|---|---|
| Java | OpenJDK 21.0.12（apt） | LTS；Neo4j 5.26 支持 Java 17/21；生态兼容面最广 | 高 | 强 |
| Maven | 3.9.12（apt） | 当前 3.9 稳定线；与 Java 21 兼容 | 高 | 强 |
| MySQL | 8.4 LTS（Docker） | Ubuntu 源是 9.7 创新版；8.4 是长期支持版 | 高 | 强 |
| Neo4j | 5.26 LTS Community（Docker） | 官方 LTS；无需在宿主机单独维护 Java 版本 | 高 | 强 |
| Docker | 29.7.2（Ubuntu 源） | 26.10 可直接安装，避免 Docker 官方源尚未支持新 codename | 高 | 强 |
| Compose | 2.40.3（Ubuntu 源） | 与 Docker 包配套 | 高 | 强 |

### 2.1 为什么 Java 选 21，不选 25

- 21 是 LTS，企业项目和中间件支持最完整；
- Neo4j 5.26 LTS 的宿主 Java 要求是 17/21，选 21 可以保留以后原生安装 Neo4j 的可能；
- 安装 `maven` 包会附带 `default-jre-headless`（当前为 Java 25 JRE），这是包依赖，不影响使用；通过 `JAVA_HOME` 固定为 21 即可。

### 2.2 为什么 MySQL 用 Docker

Ubuntu 26.10 源里的 `mysql-server` 是 `9.7.2`，属于创新版，版本节奏快、生命周期短。MySQL 官方 APT 仓库通常只跟随 Ubuntu LTS，26.10 不一定有对应仓库。使用 `mysql:8.4` 官方镜像可以固定 LTS 版本，且不污染宿主系统。

### 2.3 为什么 Neo4j 用 Docker

- Ubuntu 源没有 Neo4j 包；
- 原生安装需要维护 tar 包、systemd 单元和 Java 版本；
- Docker 镜像自带匹配的 JRE，升级和回滚只需换镜像 tag；
- 社区版足够本地开发，生产集群/RBAC 才需要企业版。

## 4. 总体结构与存储位置

```text
宿主机 Ubuntu 26.10
├── /usr/lib/jvm/java-21-openjdk-amd64     Java 21
├── /usr/share/maven + ~/.m2               Maven 与本地仓库
├── Docker Engine
│   ├── dev-mysql   127.0.0.1:3306
│   └── dev-neo4j   127.0.0.1:7474 / 7687
├── /var/lib/docker                       镜像、容器、命名卷
└── ~/dev-stack                           compose、.env、备份
```

| 内容 | 存储位置 | 预估占用 |
|---|---|---|
| Java 21 | `/usr/lib/jvm/java-21-openjdk-amd64` | 约 300MB |
| Maven 程序 | `/usr/share/maven` | 约 10MB |
| Maven 本地仓库 | `~/.m2/repository` | 1GB 起，随项目增长 |
| Docker 程序与镜像 | `/var/lib/docker` | 基础 2–3GB |
| MySQL 数据 | 命名卷 `dev-mysql-data` | 初始数百 MB |
| Neo4j 数据 | 命名卷 `dev-neo4j-data` | 初始数百 MB |
| Neo4j 日志/导入/插件 | `dev-neo4j-logs` / `dev-neo4j-import` / `dev-neo4j-plugins` | 按使用增长 |
| Compose 与环境变量 | `~/dev-stack/docker-compose.yml`、`.env` | 极小 |
| 备份 | `~/dev-stack/backups` | 按数据量 |

> `/data` 挂载后，建议把备份目录和后续大体积数据迁移过去；第一批先使用命名卷，避免依赖尚未挂载的分区。

## 5. 风险分级

| 措施 | 收益 | 风险 | 可逆性 | 结论 |
|---|---|---|---|---|
| apt 安装基础工具 | 高 | 低 | 可卸载 | 做 |
| Java 21 + Maven | 高 | 低 | 可卸载 | 做 |
| Docker Engine | 高 | 中（守护进程、docker 组近似 root） | 可卸载 | 做 |
| MySQL 8.4 容器 | 高 | 中（数据卷误删） | 有备份可恢复 | 做，先备份策略 |
| Neo4j 5.26 容器 | 高 | 中（内存占用） | 有备份可恢复 | 做，限制内存 |
| 端口绑定 127.0.0.1 | 高 | 低 | 改 compose 即可 | 必做 |
| `.env` 保存密码 | 方便 | 中（误提交/泄露） | 可轮换 | `chmod 600`，不进 Git |
| `docker compose down -v` | 清理彻底 | 高（删除数据卷） | 不可逆 | 禁止随手执行 |
| 原生安装 MySQL 9.7 | 少一层容器 | 中（创新版、升级快） | 可卸载 | 不做 |
| 原生安装 Neo4j | 少一层容器 | 中（Java/服务维护） | 可卸载 | 暂不做 |
| 开放 3306/7474/7687 到局域网 | 远程访问 | 高（未启用 UFW） | 可关闭 | 不做，用 SSH 隧道 |

### 阶段 2：Java 21 + Maven

```bash
sudo apt install -y openjdk-21-jdk maven

# 固定默认 Java 为 21
sudo update-alternatives --set java /usr/lib/jvm/java-21-openjdk-amd64/bin/java
sudo update-alternatives --set javac /usr/lib/jvm/java-21-openjdk-amd64/bin/javac

# 写入 JAVA_HOME
cat >> ~/.bashrc <<'EOF'

# Java 21
export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64
export PATH="$JAVA_HOME/bin:$PATH"
EOF

source ~/.bashrc
```

验证：

```bash
java -version
javac -version
echo "$JAVA_HOME"
mvn -version
```

预期：

- `java -version` 显示 21.0.12；
- `mvn -version` 显示 Maven 3.9.12，Java version 21.0.12；
- 如果 `mvn -version` 显示 Java 25，说明 `JAVA_HOME` 未生效，检查 `~/.bashrc` 是否被当前 shell 加载。

说明：

- `maven` 包会额外安装 `default-jre-headless`（Java 25 JRE），这是 Debian 包依赖，不会替代 JDK 21；
- 项目构建优先使用项目自带的 `mvnw`，全局 Maven 只作为兜底；
- 本地仓库在 `~/.m2/repository`，后续可能增长到数 GB；
- 如不希望引入 Java 25 JRE，可改用 Maven 官方 tar 包安装到 `/opt/maven`，见附录 A。

可选：Maven 编译冒烟测试。

```bash
mkdir -p /tmp/mvn-smoke/src/main/java/demo
cat > /tmp/mvn-smoke/pom.xml <<'EOF'

cd /tmp/mvn-smoke && mvn -q package && java -cp target/classes demo.App
```

### 阶段 3：Docker Engine + Compose

```bash
sudo apt install -y docker.io docker-compose-v2
sudo systemctl enable --now docker

# 配置日志轮转，防止日志占满根分区
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json >/dev/null <<'EOF'
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "50m",
    "max-file": "3"
  }
}
EOF

sudo systemctl restart docker

sudo usermod -aG docker "$USER"
# 退出并重新登录，或执行 newgrp docker
```

验证：

```bash
docker version
docker compose version
docker info --format '{{.Driver}} {{.DockerRootDir}}'
```

预期：Docker 29.7.2、Compose 2.40.3，数据目录 `/var/lib/docker`。

说明：

- `docker` 组等价于 root 权限，只对本机可信用户开放；
- 如果 `/etc/docker/daemon.json` 已存在，必须合并配置，不要直接覆盖；
- Ubuntu 26.10 的 Docker 官方源可能尚未提供对应 codename，本方案使用 Ubuntu 源，版本足够新；
- 不安装 Docker Desktop，Linux 上直接用 Engine。

### 阶段 4：MySQL 8.4 + Neo4j 5.26

#### 4.1 创建目录与环境变量

```bash
mkdir -p ~/dev-stack/backups
cd ~/dev-stack
umask 077

cat > .env <<EOF
MYSQL_ROOT_PASSWORD=$(openssl rand -hex 24)
MYSQL_DATABASE=devdb
MYSQL_USER=devuser
MYSQL_PASSWORD=$(openssl rand -hex 24)
NEO4J_PASSWORD=$(openssl rand -hex 24)
EOF

chmod 600 .env
printf '.env\nbackups/\n' > .gitignore
```

查看生成的密码并存入密码管理器：

```bash
cat ~/dev-stack/.env
```

> `.env` 不要提交到 Git，不要发到聊天工具；如泄露，按 4.5 节轮换密码。

#### 4.2 写入 compose 文件

```bash
cat > ~/dev-stack/docker-compose.yml <<'EOF'
name: dev-stack

services:
  mysql:
    image: mysql:8.4
    container_name: dev-mysql
    restart: unless-stopped
    ports:
      - "127.0.0.1:3306:3306"
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
      MYSQL_DATABASE: ${MYSQL_DATABASE}
      MYSQL_USER: ${MYSQL_USER}
      MYSQL_PASSWORD: ${MYSQL_PASSWORD}
      TZ: Asia/Shanghai
    command:
      - --character-set-server=utf8mb4
      - --collation-server=utf8mb4_0900_ai_ci
      - --innodb-buffer-pool-size=512M
    volumes:
      - mysql-data:/var/lib/mysql
    healthcheck:
      test: ["CMD-SHELL", "mysqladmin ping -h 127.0.0.1 -uroot -p\"$$MYSQL_ROOT_PASSWORD\" --silent"]
      interval: 10s
      timeout: 5s
      retries: 12
      start_period: 30s
    mem_limit: 2g

  neo4j:
    image: neo4j:5.26-community
    container_name: dev-neo4j
    restart: unless-stopped
    ports:
      - "127.0.0.1:7474:7474"
      - "127.0.0.1:7687:7687"
    environment:
      NEO4J_AUTH: neo4j/${NEO4J_PASSWORD}
      NEO4J_server_memory_heap_initial__size: 512m
      NEO4J_server_memory_heap_max__size: 1g
      NEO4J_server_memory_pagecache_size: 512m
      TZ: Asia/Shanghai
    volumes:
      - neo4j-data:/data
      - neo4j-logs:/logs
      - neo4j-import:/var/lib/neo4j/import
      - neo4j-plugins:/plugins
    mem_limit: 2g

volumes:
  mysql-data:
    name: dev-mysql-data
  neo4j-data:
    name: dev-neo4j-data
  neo4j-logs:
    name: dev-neo4j-logs
  neo4j-import:
    name: dev-neo4j-import
  neo4j-plugins:
    name: dev-neo4j-plugins
EOF
```

说明：

- 端口全部绑定 `127.0.0.1`，局域网无法直接访问；
- MySQL 使用 `utf8mb4`，buffer pool 限制 512MB；
- Neo4j heap 512MB–1GB，page cache 512MB，容器上限 2GB；
- 使用固定命名卷，删除/重建容器不会丢数据；
- 镜像 tag 固定大版本，不使用 `latest`。

#### 4.3 启动

```bash
cd ~/dev-stack
docker compose pull
docker compose up -d
docker compose ps
```

查看启动日志：

```bash
docker compose logs --tail=100 mysql
docker compose logs --tail=100 neo4j
```

等待 MySQL 健康：

```bash
docker inspect --format '{{.State.Health.Status}}' dev-mysql
```

预期为 `healthy`。Neo4j 没有配置 healthcheck，用 4.4 节的 Cypher 查询确认。

#### 4.4 验证服务

```bash
cd ~/dev-stack
set -a; source .env; set +a

# MySQL：版本与库
docker exec -it dev-mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" \
  -e "SELECT VERSION() AS version; SHOW DATABASES;"

# MySQL：应用账号
docker exec -it dev-mysql mysql -u"$MYSQL_USER" -p"$MYSQL_PASSWORD" "$MYSQL_DATABASE" \
  -e "SELECT VERSION() AS version, DATABASE() AS db;"

# Neo4j：Bolt 查询
docker exec -it dev-neo4j cypher-shell -u neo4j -p "$NEO4J_PASSWORD" \
  "RETURN 1 AS ok;"

# Neo4j Browser
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:7474
```

可选：写入一条测试数据。

```bash
docker exec -it dev-neo4j cypher-shell -u neo4j -p "$NEO4J_PASSWORD" \
  "CREATE (a:Person {name:'Alice'})-[:KNOWS]->(b:Person {name:'Bob'}); MATCH (n) RETURN n;"
```

#### 4.5 密码轮换

密码泄露或需要重置时：

```bash
cd ~/dev-stack
docker compose down

# 修改 .env 中的 MYSQL_PASSWORD / NEO4J_PASSWORD
# MySQL root 密码在数据卷初始化后不会因环境变量改变，需要进容器修改：
docker compose up -d mysql
docker exec -it dev-mysql mysql -uroot -p"<旧密码>" \
  -e "ALTER USER '$MYSQL_USER'@'%' IDENTIFIED BY '<新密码>';"

# Neo4j 密码通过环境变量在启动时生效
docker compose up -d neo4j
```

> 修改 `.env` 后务必同步更新密码管理器中的记录。

### 阶段 6：备份与固化

#### 6.1 MySQL 备份

```bash
cd ~/dev-stack
set -a; source .env; set +a
mkdir -p backups

docker exec dev-mysql mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" \
  --all-databases --single-transaction --routines --triggers \
  > "backups/mysql-$(date +%F).sql"

ls -lh backups/
```

恢复：

```bash
docker exec -i dev-mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" < backups/mysql-YYYY-MM-DD.sql
```

#### 6.2 Neo4j 备份

社区版没有在线热备，先停容器再做卷备份：

```bash
cd ~/dev-stack
docker compose stop neo4j

docker run --rm \
  -v dev-neo4j-data:/data \
  -v "$HOME/dev-stack/backups":/backup \
  alpine sh -c 'tar czf /backup/neo4j-$(date +%F).tar.gz -C /data .'

docker compose start neo4j
```

恢复（确认备份文件存在后再执行）：

```bash
docker compose stop neo4j
docker run --rm \
  -v dev-neo4j-data:/data \
  -v "$HOME/dev-stack/backups":/backup \
  alpine sh -c 'rm -rf /data/* && tar xzf /backup/neo4j-YYYY-MM-DD.tar.gz -C /data'
docker compose start neo4j
```

> `rm -rf /data/*` 只作用于 Neo4j 数据卷容器内部，但仍是破坏性操作；执行前确认备份可读。

#### 6.3 固化

- 观察 3–7 天，确认 MySQL/Neo4j 无异常退出；
- 容器设置了 `restart: unless-stopped`，Docker 开机自启；
- 每月执行一次备份，并把 `~/dev-stack/backups` 复制到 `/data` 或外部磁盘；
- 不建议把 `.env` 和备份放进代码仓库。

可选别名：

```bash
cat >> ~/.bashrc <<'EOF'

# dev-stack
alias dcup='docker compose -f ~/dev-stack/docker-compose.yml up -d'
alias dcdown='docker compose -f ~/dev-stack/docker-compose.yml down'
alias dcps='docker compose -f ~/dev-stack/docker-compose.yml ps'
alias dclogs='docker compose -f ~/dev-stack/docker-compose.yml logs -f --tail=100'
EOF
source ~/.bashrc
```

## 7. 日常使用与连接信息

| 数据库 | `devdb` |
| 应用用户 | `devuser` |
| 密码 | `~/dev-stack/.env` 中的 `MYSQL_PASSWORD` |
| JDBC URL | `jdbc:mysql://127.0.0.1:3306/devdb?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false` |
| 管理入口 | `docker exec -it dev-mysql mysql -uroot -p` |

> `useSSL=false` 只用于本机开发；生产环境必须启用 TLS，并使用密钥管理服务保存凭据。

### 7.3 Neo4j 连接

| 项目 | 值 |
|---|---|
| Browser | `http://localhost:7474` |
| Bolt | `bolt://127.0.0.1:7687` |
| 用户 | `neo4j` |
| 密码 | `~/dev-stack/.env` 中的 `NEO4J_PASSWORD` |
| 默认数据库 | `neo4j` |
| CLI | `docker exec -it dev-neo4j cypher-shell -u neo4j -p` |

### 7.4 内存预算

| 组件 | 上限 |
|---|---|
| MySQL 容器 | 2GB |
| Neo4j 容器 | 2GB |
| Qoder / IDE | 2–3GB |
| 浏览器 | 2GB |
| 系统与其他 | 2–3GB |

## 8. 回滚手册

| 操作 | 回滚方式 |
|---|---|
| 停止并删除容器（保留数据） | `cd ~/dev-stack && docker compose down` |
| 删除容器和所有数据卷 | `docker compose down -v`（不可逆，先备份） |
| 暂停 MySQL | `docker compose stop mysql` |
| 暂停 Neo4j | `docker compose stop neo4j` |
| 重置 Neo4j 数据 | `docker compose down`，删除卷 `dev-neo4j-data` 后重新 `up -d` |
| 重置 MySQL 数据 | `docker compose down`，删除卷 `dev-mysql-data` 后重新 `up -d` |
| 卸载 Java/Maven | `sudo apt remove --purge openjdk-21-jdk maven`，`~/.m2` 手动删除 |
| 恢复默认 Java | `sudo update-alternatives --config java` |
| 卸载 Docker | `sudo apt remove --purge docker.io docker-compose-v2`，`/var/lib/docker` 手动删除 |
| 移除 docker 组 | `sudo gpasswd -d "$USER" docker` |
| 删除配置 | `rm -rf ~/dev-stack`（先备份 `.env` 和 `backups`） |

## 10. 待确认事项

执行前需要确认：

1. Java 使用 21 LTS 是否符合现有项目要求？如果项目必须用 25，则改为 `openjdk-25-jdk`，但原生 Neo4j 兼容性会变差。
2. MySQL 是否必须用 9.x？默认选 8.4 LTS；如果项目依赖 9.x 特性，改用 `mysql:9.7` 镜像。
3. Neo4j 是否需要 APOC 或 GDS？默认不装，有需求再单独加插件并评估内存。
4. 是否需要从宿主机以外的设备访问数据库？默认只开本机，远程访问建议 SSH 隧道。
5. 是否有现成 MySQL/Neo4j 数据需要导入？有的话先确认字符集、版本和备份。
6. 是否现在挂载 `/data`？本方案不依赖它，后续迁移备份和大数据时再处理。
7. `.env` 密码是否已存入密码管理器？没有的话先完成这一步再启动服务。

## 附录 A：不使用 Docker 的原生方案（备选）

仅在明确不接受容器时使用。

### A.1 Maven 官方 tar 包

```bash
# 以官网当前 3.9.x 版本为准
curl -fLO https://dlcdn.apache.org/maven/maven-3/3.9.12/binaries/apache-maven-3.9.12-bin.tar.gz
sudo tar -xzf apache-maven-3.9.12-bin.tar.gz -C /opt
sudo ln -sfn /opt/apache-maven-3.9.12 /opt/maven
sudo ln -sfn /opt/maven/bin/mvn /usr/local/bin/mvn
mvn -version
```

优点：不引入 Java 25 JRE；版本固定。
缺点：升级需要手动替换目录。

### A.2 MySQL 原生安装

```bash
sudo apt install -y mysql-server
```

注意：

- Ubuntu 26.10 提供的是 MySQL 9.7 创新版，不是 8.4 LTS；
- 安装后会占用 3306，必须先停止并禁用原生服务，才能启动容器版；
- 数据目录 `/var/lib/mysql`，升级前必须备份；
- 如必须使用 8.4 LTS，优先考虑 Docker，而不是混用非官方仓库。

### A.3 Neo4j 原生安装

需要：

- 官方 tar 包；
- Java 21；
- 独立系统用户；
- systemd 单元；
- 手动配置 `neo4j.conf` 的监听地址、内存和认证。

原生安装的维护成本高于 Docker，不建议作为第一批方案。
