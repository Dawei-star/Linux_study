# Linux 安装 Codex 桌面版（ChatGPT 桌面应用预览版）

> 版本：0.0.1（首次沉淀）
> 日期：2026-10-20
> 状态：已完成（下载与校验由本地执行；安装由使用者执行并确认，GUI 启动未独立复测）
> 环境：Lenovo Legion Y7000P IRH8 / Ubuntu 26.10 / GNOME 51 / Wayland / amd64
> 一句话结论：Linux 上没有独立的 Codex 桌面 app，官方形态是 ChatGPT 桌面应用预览版内置 Codex；从官方 CDN 下载 `chatgpt` 26.1013.40934 的 deb（502,087,434 字节，SHA-256 已记录），断点续传完成后用 `apt` 本地安装，仅需从源补 `libssl3t64`。

---

## 1. 结论摘要

- 起点是 `npm install -g @openai/codex` 报 `EACCES`，根因是 apt 版 npm 的全局前缀为 `/usr/local`（root 所有），与 Codex 本身无关。
- 桌面端走独立路线：官方 Linux 包为 `chatgpt` 26.1013.40934（amd64），安装后命令 `chatgpt`，Codex 作为应用内工作区使用，不依赖本机 Node。
- 官方 CDN 单连接约 0.4 MB/s，13 分钟处被重置（190,417,598 / 502,087,434 字节）；`curl -C -` 新连接续传约 4 MB/s 完成，最终字节数与 `Content-Length` 完全一致。
- 包内自带 AppArmor 配置并允许 `userns`，规避 Ubuntu 24.04+ 的非特权用户命名空间限制；`apt-get -s` 在 26.10 上只需新增 `libssl3t64`。
- 官方支持列表未包含 26.10，属于“比测试范围新”的预览使用，后续升级/异常需按未决事项处理。

## 2. 背景与目标

### 2.1 背景

- 2026-10-20 17:01 左右执行 `npm install -g @openai/codex`，报错：
  `EACCES: permission denied, mkdir '/usr/local/lib/node_modules'`。
- 只读检查：`npm config get prefix` 为 `/usr/local`，该目录下 `lib/node_modules` 不存在；
  `/usr/local/bin` 为 `root:root 755`；`node`/`npm` 均来自 `/usr/bin`（Node 24.19.0、npm 11.16.0）。
- 使用者随后要求安装“Linux 的 Codex 桌面版本”。

### 2.2 目标

1. 确认 Linux 是否存在官方 Codex 桌面端，并取得官方安装包。
2. 下载过程可校验：来源、字节数、包元数据、依赖可解析。
3. 不修改系统级 npm 前缀，不使用 VPN/代理或第三方重打包。
4. 安装动作交给使用者执行 sudo；文档保留回滚方式。

### 2.3 非目标

- 不完成 `npm -g` 的全局修复（属于 CLI 路线，另行处理）。
- 不安装 `codex-desktop-linux` 等社区重打包版本。
- 不在本文档中记录登录、账号或令牌信息。
- 不验证 Codex 的具体功能表现（GUI 由使用者实际操作）。

| 阶段 | 观测 |
|---|---|
| 单连接首轮 | 平均约 0.24–0.4 MB/s；13 分钟时 `curl: (56) Recv failure: 连接被对方重置`，停在 `190417598` 字节（37%） |

## 5. 已执行操作

```bash
# 1. 下载（可重复执行，自动续传）
mkdir -p ~/Downloads && cd ~/Downloads
curl -L -C - --retry 5 --retry-all-errors --retry-delay 3 \
  -o chatgpt_amd64.deb \
  https://persistent.oaistatic.com/codex-app-prod/linux/deb/latest/chatgpt_amd64.deb

# 2. 校验大小与哈希
stat -c '%s' chatgpt_amd64.deb        # 期望 502087434
sha256sum chatgpt_amd64.deb

# 3. 校验包结构与依赖（不需要 root）
dpkg-deb -f chatgpt_amd64.deb Package Version Architecture Maintainer
dpkg-deb -c chatgpt_amd64.deb > /dev/null
apt-get -s install ./chatgpt_amd64.deb

# 4. 安装（由使用者执行）
sudo apt install ~/Downloads/chatgpt_amd64.deb
```

安装位置与入口：

| 项 | 路径 |
|---|---|
| 主程序 | `/usr/lib/chatgpt/` |
| 命令 | `/usr/bin/chatgpt` |
| 桌面入口 | `/usr/share/applications/chatgpt.desktop` |
| AppArmor | `/etc/apparmor.d/chatgpt` |

## 6. 取舍理由

1. **优先官方分发包**：`persistent.oaistatic.com` 是官方下载页指向的 CDN，包元数据维护者为 OpenAI，且自带 AppArmor 配置；社区重打包虽然可能兼容更多发行版，但引入第三方信任与更新滞后。
2. **不修 npm 全局前缀来完成这次目标**：桌面端不依赖 Node；修 npm 前缀是另一条独立需求，混在一起会让排障边界不清。CLI 备选方案为 `npm config set prefix ~/.local` 并把 `~/.local/bin` 加入 PATH。
3. **续传而不是重下**：官方 CDN 对长连接有重置现象，但 Range 请求返回 `206`，`curl -C -` 可安全续传；重下 479 MiB 没有必要。
4. **接受 26.10 的预览风险**：依赖解析与 AppArmor 限制均已验证，剩余风险是应用自身的版本校验或桌面集成问题，属于可回滚风险。

## 7. 回滚方式

```bash
# 卸载应用（保留用户数据时可去掉 --purge）
sudo apt remove --purge chatgpt

# 如不再需要依赖
sudo apt autoremove

# 删除安装包
rm ~/Downloads/chatgpt_amd64.deb
```

`/etc/apparmor.d/chatgpt` 由包管理，卸载时一并移除。用户配置目录若残留，可按需手动清理（位置待确认，未在本次检查中列举）。
